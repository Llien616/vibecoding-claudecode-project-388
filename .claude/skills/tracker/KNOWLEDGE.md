# KNOWLEDGE.md — правила значимости изменений цен

Документ описывает, какие изменения между прогонами трекера считаются
**значимыми**. Правила применяются к паре «текущий прогон» → «предыдущий прогон».

## База для сравнения

- **Прошлый прогон** — последний по дате файл `YYYY-MM-DD.json` в репозитории
  `Llien616/tracker-data`, который старше текущей даты прогона.
- Сравнение идёт **по URL**: строка текущего прогона сопоставляется со строкой
  прошлого прогона с тем же `url` (URL сравнивается как есть, без нормализации
  query-параметров).
- Если прошлого прогона нет (самый первый запуск), базы для сравнения нет:
  все URL текущего прогона считаются новыми (правило 4).

## Обозначения

| Поле | Смысл |
|---|---|
| `regular_price` | обычная цена, «С другими банками» |
| `sale_price` | цена с Ozon Картой, «С банками» |
| `has_credit` | всегда `false`, в правилах не участвует |
| `—` / `null` | цена отсутствует (товара нет в продаже, цена не показана) |

Цены перед сравнением приводятся к числу: убираются пробелы (включая
неразрывные), символ `₽` и разделители тысяч; `1 428 ₽` → `1428`.
Некорректная или отсутствующая цена трактуется как «цена отсутствует».

## Правила

### Правило 1. Изменение `regular_price` на 5 % и более

Значимо, если обычная цена изменилась **в любую сторону** (рост или падение)
на 5 % и более относительно прошлого значения:

```text
abs(new_regular - old_regular) / old_regular * 100 >= 5
```

- Порог включительный: ровно 5 % — уже значимо.
- Изменение меньше 5 % — не значимо.
- Если `old_regular` отсутствует или равен 0, правило 1 не применяется
  (оцениваются только правила 2–5).

### Правило 2. Появилась `sale_price`

Значимо, если в прошлом прогоне `sale_price` не было (`—` / `null`),
а в текущем она появилась с числовым значением.

### Правило 3. `sale_price` стала меньше

Значимо, если `sale_price` была и в прошлом, и в текущем прогоне, и текущее
значение **строго меньше** прошлого (`new_sale < old_sale`).

Рост `sale_price` значимым не считается.

### Правило 4. Новый URL

Значимо, если `url` отсутствовал в прошлом прогоне, а в текущем появился.

### Правило 5. URL пропал

Значимо, если `url` был в прошлом прогоне, а в текущем его нет
(товар снят, ссылка удалена, страница не получена).

## Сводная таблица

| # | Событие | Значимо |
|---|---|---|
| 1 | `regular_price` изменилась на ≥ 5 % (вверх или вниз) | да |
| 1 | `regular_price` изменилась менее чем на 5 % | нет |
| 2 | `sale_price` была `—` и появилась | да |
| 3 | `sale_price` уменьшилась | да |
| 3 | `sale_price` выросла | нет |
| — | `sale_price` исчезла (была и пропала) | нет (правилами не покрыто) |
| 4 | URL новый | да |
| 5 | URL пропал | да |
| — | ничего не изменилось | нет |

## Формат результата проверки

По каждому значимому событию — одна запись:

```json
{
  "rule": 1,
  "url": "https://www.ozon.ru/product/…-5247783662",
  "field": "regular_price",
  "previous": "1 462 ₽",
  "current": "1 428 ₽",
  "change_percent": -2.33,
  "reason": "regular_price changed by 2.33% (threshold 5%)"
}
```

- `rule` — номер правила (1–5).
- `field` — `regular_price`, `sale_price` или `url`.
- `previous` / `current` — значения до и после; для отсутствующих — `null`.
- `change_percent` — только для правила 1, с округлением до двух знаков.
- `reason` — короткое пояснение на английском.

Если значимых событий нет, результат — пустой массив `[]`.

## Примеры

**Пример 1.** Было `3 888 ₽`, стало `3 699 ₽` → изменение −4.86 % → **не значимо**.

**Пример 2.** Было `522 ₽`, стало `490 ₽` → −6.13 % → **значимо** (правило 1).

**Пример 3.** Было `sale_price: "—"`, стало `"470 ₽"` → **значимо** (правило 2).

**Пример 4.** Было `"1 285 ₽"`, стало `"1 299 ₽"` → подорожание при неизменной
`regular_price` → **не значимо**.

**Пример 5.** В прошлом прогоне 5 URL, в текущем 4 (пропал `…-2624612136`) →
**значимо** (правило 5), и запись о нём формируется по данным прошлого прогона.

## Границы применимости

- Правила описывают **только изменения между прогонами**; фильтрацию по
  абсолютной цене, скидкам и рейтингу они не задают.
- Уведомления (Telegram) получают только значимые события; полный прогон
  по-прежнему публикуется в `Llien616/tracker-data` целиком.
- Если правило нужно изменить, правится этот файл — скилл `tracker` и его
  скрипты на правила не завязаны.
