# Трекер цен

Полный цикл: собрать цены → сравнить с предыдущим прогоном → опубликовать прогон →
вывести значимые изменения.

## Список товаров

Ссылки лежат в `urls.txt` рядом с этим файлом (одна на строку, `#` — комментарий).
Чтобы изменить набор товаров, редактируй `urls.txt`, а не скилл.

## Запуск

```bash
node .claude/skills/tracker/scripts/track.mjs
```

Порядок работы:

1. `run.mjs` собирает цены по всем URL (через скрипты `extract-price`, пауза 20 с).
2. `track.mjs` получает список файлов репозитория `Llien616/tracker-data` и читает
   **последний по дате файл — предыдущий прогон** (строго раньше текущей даты).
   Если прошлых прогонов нет, сравнение пропускается.
3. Товары сопоставляются **по `url`**, для каждого сравниваются `regular_price`
   и `sale_price`; применяются правила из `KNOWLEDGE.md`.
4. Прогон публикуется как `YYYY-MM-DD.json` — один коммит через коннектор GitHub.
5. В stdout выводится **массив только значимых изменений** (пустой массив, если
   ничего значимого не произошло).

Флаги:

```bash
node .claude/skills/tracker/scripts/track.mjs --limit=2        # отладка: 2 товара
node .claude/skills/tracker/scripts/track.mjs --no-publish     # без записи в репозиторий
node .claude/skills/tracker/scripts/track.mjs --date=2026-11-07
```

Отдельные шаги (для отладки):

```bash
node .claude/skills/tracker/scripts/run.mjs                 # JSON-массив прогона
node .claude/skills/tracker/scripts/compare.mjs --file=run.json
node .claude/skills/tracker/scripts/publish.mjs --file=run.json
node .claude/skills/tracker/scripts/run.mjs --table         # таблица для человека
```

## Сравнение прогонов

- База — последний по дате `YYYY-MM-DD.json` в репозитории, который старше даты
  текущего прогона. Нет таких файлов — сравнивать не с чем, изменений не выводим.
- Сопоставление только по `url`; поля `regular_price` и `sale_price`.
- Учитываются только правила из `KNOWLEDGE.md`:

| # | Событие | Значимо |
|---|---|---|
| 1 | `regular_price` изменилась на ≥ 5 % (вверх или вниз) | да |
| 2 | `sale_price` не было (`—`/`null`), а появилась | да |
| 3 | `sale_price` стала меньше | да |
| 4 | `url` не было в прошлом прогоне, а появился | да |
| 5 | `url` был в прошлом прогоне, а пропал | да |

Всё остальное (рост `sale_price`, изменение `regular_price` меньше 5 %,
исчезновение `sale_price`, неизменные позиции) в вывод **не попадает**.

Цены перед сравнением нормализуются: `1 428 ₽` → `1428` (пробелы, неразрывные
пробелы и `₽` отбрасываются). Полные правила и примеры — в `KNOWLEDGE.md`.

## Формат вывода

JSON-массив событий, одна запись на значимое изменение:

```json
[
  {
    "rule": 1,
    "url": "https://www.ozon.ru/product/…-5659780691",
    "field": "regular_price",
    "previous": "522 ₽",
    "current": "490 ₽",
    "change_percent": -6.13,
    "reason": "regular_price changed by -6.13% (threshold 5%)"
  },
  {
    "rule": 4,
    "url": "https://www.ozon.ru/product/…-9999999999",
    "field": "url",
    "previous": null,
    "current": "https://www.ozon.ru/product/…-9999999999",
    "reason": "new url"
  }
]
```

- `rule` — номер правила 1–5, `field` — `regular_price`, `sale_price` или `url`.
- `previous` / `current` — значения до и после; отсутствующее — `null`.
- `change_percent` — только для правила 1.
- У одного товара может быть несколько записей (например, правило 1 и правило 3).
- Нет значимых изменений — `[]`. Дополнительных пояснений в ответ не добавлять.

## Сохранение результата

1. **Файл — JSON, имя `YYYY-MM-DD.json`**, дата — дата прогона (локальная).
   Один файл на прогон; повторный прогон в тот же день обновляет файл.
2. **Файл живёт только в `Llien616/tracker-data`** (ветка `main`). Локально он не
   сохраняется: никаких `git clone`, `git add/commit/push` и файлов в проекте.
3. **Запись — через коннектор GitHub**: MCP-инструмент (`create_or_update_file` /
   `push_files`) либо эквивалентный `PUT` в `scripts/lib/github.mjs`
   (`writeRun`). Один прогон = один коммит.

Формат файла прогона:

```json
[
  {
    "url": "https://www.ozon.ru/product/…-731553575",
    "regular_price": "3 888 ₽",
    "sale_price": "3 499 ₽",
    "has_credit": false
  }
]
```

- `regular_price` — обычная цена («С другими банками»).
- `sale_price` — цена с Ozon Картой («С банками»).
- `has_credit` — всегда `false`.
- Не удалось получить товар — в ценах `—`, причина в stderr (JSON не ломается).

## Правила

- Порядок строк — как в `urls.txt`.
- Пауза 20 с между запросами цен — обязательна, не уменьшать.
- Не дублировать логику `extract-price` (загрузка, антибот, парсинг цен).
- Не дублировать правила значимости: единственный источник — `KNOWLEDGE.md`.
- Не сохранять прогон локально — только коммит в `Llien616/tracker-data`.
