# Трекер цен

Прогоняет фиксированный список товаров через скилл `extract-price` и сохраняет
результат **одним файлом в репозиторий `Llien616/tracker-data`**: одна запись
на товар.

## Список товаров

Ссылки лежат в `urls.txt` рядом с этим файлом (одна на строку, `#` — комментарий).
Чтобы изменить набор товаров, редактируй `urls.txt`, а не скилл.

## Запуск

```bash
# 1) прогон: JSON-массив в stdout, прогресс — в stderr
node .claude/skills/tracker/scripts/run.mjs

# 2) запись результата в репозиторий: один вызов коннектора = один коммит
node .claude/skills/tracker/scripts/run.mjs | node .claude/skills/tracker/scripts/publish.mjs

# посмотреть таблицей, ничего не коммитить
node .claude/skills/tracker/scripts/run.mjs --table
```

Полезные флаги:

```bash
node .claude/skills/tracker/scripts/run.mjs --limit=2        # только первые 2 товара
node .claude/skills/tracker/scripts/publish.mjs --file=run.json --date=2026-11-06
```

## Как это работает

Скрипт **не содержит своей логики разбора цен** — он по очереди вызывает скрипты
скилла `extract-price`:

1. `fetch_page.mjs` — загрузка карточки через видимый Chrome + CDP;
2. `extract_price.mjs` — разбор сохранённого HTML и извлечение цен.

Между запросами цен скрипт выдерживает паузу **20 секунд**. Меняется парсинг
или обход блокировки — правится только `extract-price`, трекер подхватит
изменения автоматически.

## Сохранение результата (обязательные требования)

1. **Файл — JSON, имя `YYYY-MM-DD.json`**, где дата — дата прогона
   (локальная дата машины). Один файл на прогон, повторный прогон в тот же день
   перезаписывает файл.
2. **Файл живёт только в репозитории `Llien616/tracker-data`** (ветка `main`).
   Локально он не сохраняется: никакого `git clone`, `git add/commit/push` и
   файлов в рабочей папке проекта.
3. **Запись выполняется через коннектор GitHub.** В Claude Code — MCP-инструмент
   записи файла (`create_or_update_file` / `push_files`), который создаёт коммит
   сразу в удалённом репозитории. Скрипт `publish.mjs` делает ровно то же самое
   (один `PUT /repos/Llien616/tracker-data/contents/<date>.json`) и нужен только
   там, где MCP-сервер GitHub не подключён.
4. **Один прогон = один коммит.** Не дробить файл на несколько коммитов и не
   коммитить промежуточные состояния.

Если файл `YYYY-MM-DD.json` уже существует, запись обновляет его (для этого
`publish.mjs` сначала читает `sha`), а не создаёт второй файл.

## Формат файла

JSON-массив, одна запись на товар, поля ровно такие:

```json
[
  {
    "url": "https://www.ozon.ru/product/braslet-tsepochka-iz-naturalnyh-kamney-obsidian-i-kaholong-stilnyy-podarok-v-stile-boho-731553575/?sh=F7gN070fQA",
    "regular_price": "3 888 ₽",
    "sale_price": "3 499 ₽",
    "has_credit": false
  }
]
```

- `regular_price` — обычная цена («С другими банками»).
- `sale_price` — цена с Ozon Картой («С банками»).
- `has_credit` — всегда `false` (рассрочка не является ценой товара).
- Если товар не удалось получить, в ценовых полях ставится `—`; причина пишется
  в stderr, чтобы не ломать JSON.

Проверка перед публикацией: массив непустой, порядок строк как в `urls.txt`,
в каждом объекте есть все четыре поля.

## Значимость изменений

Какие изменения между прогонами считать значимыми, описано в `KNOWLEDGE.md`
рядом с этим файлом. Кратко:

1. `regular_price` изменилась на 5 % и более (в любую сторону).
2. `sale_price` не было, а в текущем прогоне появилась.
3. `sale_price` стала меньше, чем была.
4. `url` не было в прошлом прогоне, а в текущем появился.
5. `url` был в прошлом прогоне, а в текущем пропал.

База сравнения — последний по дате файл прогона в `Llien616/tracker-data`.
Правила и формат отчёта о значимых событиях — в `KNOWLEDGE.md`.

## Правила

- Порядок строк — как в `urls.txt`.
- Пауза 20 с — обязательна, не уменьшать: Ozon отвечает блоком при частых запросах.
- Не дублировать логику `extract-price` (загрузка, антибот, парсинг цен) внутри трекера.
- Не сохранять результат локально — только коммит в `Llien616/tracker-data`.
